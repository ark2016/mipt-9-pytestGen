# 0002. Генерация по одной функции

Статус: принято.

## Контекст

Модель работает с контекстом 8192 токена на CPU и плохо держит в голове целый модуль. Запрос
с большим контекстом на CPU стоит минуты, а ошибка в одном месте не должна ломать остальное.

## Решение

Модуль разбирается статически (`analysis/ast_analyzer.py`), затем каждая функция (или метод)
обрабатывается независимо: свои цели по веткам, свои входы, свои промпты, свой бюджет.
`GenerateTests._seed` обходит функции по очереди; `SandboxError` на одной функции логируется как
`function_skipped`, остальные продолжают работать. По умолчанию пропускаются properties,
dunder-методы и `_private`-функции (приватную можно запросить явно через `--function`).
Подмножество выбирается флагом `--function` (имя функции, `Class.method` или имя класса).

Промпты короткие и содержат только одну функцию, её docstring и нужные цели
(`application/prompts.py`). Ответы кэшируются на уровне запроса, поэтому повторный прогон не
вызывает модель для тех промптов, которые не изменились.

## Последствия

- Сбой, таймаут или плохой ответ ограничены одной функцией; прогресс виден по стадиям
  (`Stage` в `ports.py`).
- Промпты помещаются в контекст малой модели и дёшево кэшируются.
- Цена: тесты не знают о взаимодействии функций и о состоянии модуля. Для методов класса
  состояние объекта придумывает модель (free-form путь), сценарии вида "сначала `add_item`,
  потом `total`" получаются только если модель сама их напишет.
