# 0003. Concolic-lite: AST path conditions + Z3, LLM как запасной решатель

Статус: принято.

## Контекст

Нужны входы, которые проводят выполнение через каждую ветку функции. Случайные входы и вопросы
к малой модели ("напиши вход, чтобы `years >= 3`") ненадёжны для арифметических и строковых
условий. Полноценный dynamic symbolic execution требует инструментации интерпретатора и слишком
тяжёл для проекта на один семестр. Идея объединять фаззинг и динамическое символьное
выполнение взята из более раннего курсового проекта автора:
[ark2016/VK-Technopark-project-2024](https://github.com/ark2016/VK-Technopark-project-2024).

## Решение

"Lite"-вариант без инструментации:

1. `analysis/branches.py` обходит AST и для каждой ветки (обе стороны, T и F) строит path condition:
   клаузы над параметрами функции с учётом выходов предыдущих блоков. Присваивания вида
   `y = x * 2` подставляются (`analysis/substitution.py`).
2. `concolic/translator.py` переводит клаузы в термы Z3. Поддержаны `int`, `float`
   (как Real), `bool`, `str`, `Optional`/`X | None`, `len()` списков, кортежей и bytes, а также
   `abs`, `min`, `max`, `isinstance`.
3. `concolic/search.py` ищет модель через `z3.Optimize` с мягкими предпочтениями: короткие
   читаемые строки, небольшие неотрицательные числа.
4. `concolic/verify.py` перепроверяет модель настоящей семантикой Python (округление float,
   порядок строк у Z3 и Python различаются).
5. Выполнение с этими входами делает отдельный шаг `sandbox/recorder.py`: фиксирует, что функция
   вернула или какое исключение подняла. Ожидаемые значения в тестах - записанное поведение.
6. Всё, что решатель не взял (`UNSUPPORTED`, `UNKNOWN`), получает `InputProposer`: модель
   предлагает входы, они валидируются по аннотациям и тоже записываются в песочнице.
   `application/boundary.py` дополнительно подмешивает граничные значения (`x > 100` даёт 99, 100,
   101), чтобы ошибки на границе (off-by-one) попадали на ревью оракула.

## Последствия

- Для арифметических и строковых условий вход строится точно и без LLM; в примере
  `shop/pricing.py` один Z3 без модели поднимает покрытие строк с 37.5% до 95.8%.
- Решатель неполон: циклы, `try`, повторные присваивания, вызовы чужих функций и методы
  экземпляра не моделируются, ветка уходит модели. Z3 ограничен по времени
  (`PYTESTGEN_Z3_TIMEOUT_MS`), строки предпочитаются короче 32 символов, жёсткий потолок 256.
- Из-за проверки в Python ложные входы отбрасываются, а не превращаются в красные тесты.
