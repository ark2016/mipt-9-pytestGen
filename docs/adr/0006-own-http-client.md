# 0006. Собственный HTTP-клиент: httpx + tenacity, моки через respx

Статус: принято.

## Контекст

Нужен один тонкий клиент для любого OpenAI-совместимого сервера (llama.cpp, Ollama, vLLM, облако)
с адресом и моделью из переменных окружения. Поведение провайдеров расходится: `response_format`
с `json_schema` понимают не все, 429 и 5xx приходят нередко, локальная модель может быть ещё не
загружена.

## Решение

`llm/client.py` (`OpenAICompatClient`) делает `POST {base_url}/chat/completions` через
`httpx.Client`.

- Повторы через `tenacity`: транспортные ошибки и статусы 429, 500, 502, 503, 504, экспоненциальная
  задержка до 30 с, учёт `Retry-After`. Число повторов: `PYTESTGEN_LLM_MAX_RETRIES`.
- HTTP 400 с упоминанием `response_format`, `json_schema` или `grammar` понижает режим навсегда:
  `json_schema -> json_object -> none` (`PYTESTGEN_LLM_JSON_MODE` задаёт стартовый режим).
- `CircuitBreakerLLMClient` (`application/availability.py`) после первой ошибки соединения не
  делает остальные запросы и сразу отвечает ошибкой, чтобы недоступная модель не съедала минуты на
  каждый промпт.
- Тесты используют `respx` (мок на уровне httpx) и записанные ответы в `tests/fixtures/llm/`;
  реальная модель нужна только тестам с маркером `slow`.

## Последствия

- Минимум зависимостей, прозрачное поведение при ошибках, в CI не нужен ни ключ, ни сервер.
- Мы сами поддерживаем кусочек протокола (стриминга и tool calls нет и не нужно).
- Отказ от `openai` SDK: он тяжелее, а вся нужная нам логика (понижение режима, circuit breaker)
  всё равно писалась бы поверх него.
