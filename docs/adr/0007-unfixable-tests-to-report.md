# 0007. Неисправимые тесты попадают в отчёт, а не в файл

Статус: принято.

## Контекст

Малая модель часто пишет тесты, которые не проходят: неверное ожидание, лишний импорт,
синтаксическая ошибка. Файл с красными тестами нельзя принимать как результат, но молча
выбрасывать их тоже нельзя: пользователь должен видеть, что произошло.

## Решение

В итоговый файл попадают только тесты, которые прошли в песочнице. Для остальных:

- Тест от модели (free-form), который упал, получает до `PYTESTGEN_REPAIR_ATTEMPTS` (2)
  попыток исправления с трассировкой в промпте (`application/repair.py`). Если не помогло, он
  удаляется и записывается как `DroppedTest` с причиной `still_failing`.
- Кейс из таблицы, который упал в прогоне, считается нестабильным (`unstable`). Код, не
  прошедший guard или парсер, получает причину `invalid_code`; значение без литерального
  представления - `not_literal`; тесты, снятые `--minimize`, - `no_coverage_gain`.
- Кейсы с вердиктом оракула `suspicious` не пишутся в файл (чтобы не закрепить, возможно,
  ошибочное поведение), а попадают в раздел "Suspected bugs" отчёта.
- Если тест упал на assertion и был переписан под поведение кода, а у функции есть docstring,
  он помечается как возможный баг: исходное ожидание могло быть верным.
- Отчёты (markdown, JSON, консоль) группируют удалённые тесты по причинам.

## Последствия

- Сгенерированный файл зелёный на момент генерации, а потерянное видно в отчёте.
- Репейр "под поведение кода" может закрепить баг; для этого и введена пометка возможного бага.
- Если ничего не удалось проверить (таймаут прогона), файл не пишется: ошибка с советом
  поднять `PYTESTGEN_RUN_TIMEOUT_S` или сузить прогон флагом `--function`.
