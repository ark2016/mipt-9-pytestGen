# 0010. structlog JSON в stderr, rich в stdout

Статус: принято.

## Контекст

У CLI две аудитории: человек, которому нужны читаемые таблицы прогресса и итогов, и CI или
скрипты, которым нужны машиночитаемые события и чистый stdout (например, `analyze --json`).

## Решение

- Логи пишутся через `structlog` как JSON-строки в stderr (`log.py`): `event`, `level`, `timestamp`
  и контекст (`function`, `purpose`, `latency_ms`, токены). Формат `console` включается
  `PYTESTGEN_LOG_FORMAT=console` или `--log-format console`; уровень задаётся
  `PYTESTGEN_LOG_LEVEL` или `--log-level`.
- Человеческий вывод - только `rich` в stdout: прогресс по стадиям (`ConsoleProgress`),
  таблицы анализа и итоговый отчёт (`report/console.py`). Ошибки пользователя идут в stderr
  с кодом выхода 2.
- Отчёты в файлы (`--report-md`, `--report-json`) пишутся отдельно и не зависят от терминала.
- Поток для логов выбирается при каждой записи (`_CurrentStderr`), чтобы подмена stderr в тестах не
  ломала логирование.

## Последствия

- `pytestgen ... 2>events.jsonl` отделяет события от вывода; в Docker-демо уровень по
  умолчанию `WARNING`, чтобы вывод оставался читаемым.
- Две системы вывода - небольшая цена за чёткое разделение: тексты для людей и события для
  машин не смешиваются.
- Сообщения об ошибках соединения могут содержать локализованный текст ОС (заметно в Windows).
