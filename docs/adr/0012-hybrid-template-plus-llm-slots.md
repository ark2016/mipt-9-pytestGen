# 0012. Гибрид: шаблон + LLM-слоты (и `--strategy llm` для сравнения)

Статус: принято.

## Контекст

Модель размера 1.5B-3B плохо пишет целые тесты: путает сигнатуры, ошибается в ожидаемых
значениях, ломает синтаксис. Зато она справляется с короткими задачами с жёстким форматом
ответа (JSON по схеме): оценить, соответствует ли поведение docstring, или предложить
несколько аргументов.

## Решение

По умолчанию (`--strategy hybrid`) каркас теста детерминирован, а модель заполняет "слоты":

1. Шаблон: `codegen/render.py` печатает `@pytest.mark.parametrize`-таблицы
   (`test_<fn>_returns`, `test_<fn>_raises`); входы дают Z3 и граничные значения, ожидаемые
   значения записывает песочница (характеризационные тесты).
2. Слот "входы": для веток, которые Z3 не решил, модель предлагает аргументы (JSON-схема).
3. Слот "оракул": модель просматривает записанное поведение по docstring и помечает
   подозрительное (`ok` / `suspicious` с объяснением).
4. Свободные тесты (free-form): методы экземпляра и цели gap-цикла, которые не взяли ни Z3,
   ни входы модели, - модель пишет функции pytest целиком, с проверкой guard и циклом
   исправления.
5. Gap-цикл (`PYTESTGEN_GAP_ITERATIONS`): по непокрытым дугам запрашиваются новые тесты; шаг без
   прироста покрытия откатывается.

`--strategy llm` пропускает шаги 1-3 и просит модель писать тесты для всех функций: это база для
сравнения "гибрид против чистой LLM" (охват, число отброшенных тестов, прирост покрытия).

## Последствия

- Ядро результата (таблицы Z3) не зависит от качества модели: без модели в примере
  `shop/pricing.py` покрытие строк растёт с 37.5% до 95.8%; модель дополняет хвост и ищет
  подозрительные места.
- Тесты, закреплённые записью поведения, фиксируют текущее поведение, а не спецификацию;
  противовес - оракул-ревью, но малая модель даёт и ложные срабатывания.
- Методы экземпляра целиком зависят от модели; при её недоступности они остаются без тестов.
